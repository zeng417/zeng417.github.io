上一篇聊了三种「自己走过去」的方式，里面反复出现一个前提：机器人手里得有一张地图。点到点也好，自主导航也好，路径规划的第一个问题永远是——图呢？

很多人第一次跑建图，看着 RViz 里那条歪歪扭扭的走廊，心里都会冒出一个问题：机器人连自己现在在哪都说不清楚，怎么就能把整层楼的图画出来？

答案就藏在这个名字里——SLAM，Simultaneous Localization and Mapping，同步定位与建图。用一句话说清楚：

> **机器人在陌生环境里一边走一边干两件事：用画出来的地图回答「我在哪」，又用「我在哪」的答案把地图接着往下画。**

两件事互为前提，同时推进。这篇文章就用最少的术语，把这件事讲清楚，最后在 ROS 2 里亲手跑出第一张地图。

适用环境：ROS 2 Humble（Ubuntu 22.04 / Docker 中的 Humble 均适用）

---

## 一、先看一个生活场景：第一次送外卖

先别急着看激光雷达，想象一个外卖骑手第一次去一个陌生的封闭式小区。

他进大门的时候，大脑里其实也在跑一个 SLAM 流程：

1. 进门先记一个参照物——大门在南边，进门右手是 3 号楼；
2. 往前走，路过喷泉，记住喷泉在小区中间；
3. 绕到 6 号楼时，回头看了一眼，发现 6 号楼正对着喷泉——这一刻他把「我刚才走过的路」修正了一下，脑子里的小区地图更准了；
4. 送完一单，第二单再去 9 号楼，他不用重新摸索了——因为地图已经在脑子里。

这里面的每个环节，都能在 SLAM 里找到一一对应的东西：

| 外卖骑手的动作 | SLAM 里的概念 |
| --- | --- |
| 记住大门、喷泉、楼的位置 | **建图（Mapping）**——把环境里的路标塞进地图 |
| 用「大门在南边」判断自己在哪 | **定位（Localization）**——根据地图回答当前位置 |
| 回头看一眼发现对上了，修正记忆 | **回环检测（Loop Closure）**——认出「这地方我来过」 |
| 走过的路线 | **里程计（Odometry）**——对「我走了多远」的估计 |

整个 SLAM，说白了就是把骑手脑子里的这套流程，用数学实现出来。

## 二、SLAM 的核心矛盾：鸡生蛋，蛋生鸡

SLAM 最难的地方，一句话就能说透：

> **想定位，你得先有地图；想建图，你得先知道自己在哪。但陌生环境里，这两个都没有。**

这就是著名的「鸡生蛋、蛋生鸡」问题。经典的做法是不要试图一步算到位，而是让两边**交替推进、互相修正**：

1. 机器人动了一小步，里程计先给个粗略估计：「我大概往前走了 1 米」；
2. 用当前这一帧激光数据，和已有的地图匹配，修正这个粗略估计——「不对，看墙上的拐角，我其实只走了 0.95 米」；
3. 用修正后的位置，把这一帧激光数据「贴」到地图上，地图扩大一点；
4. 回到第 1 步，继续走，继续匹配，继续贴。

所以「Simultaneous（同步）」这个词不是修辞——定位和建图真的是在同一秒钟内交替发生的。哪一步停了，另一步立刻就没有意义。

### 一个容易踩的坑：误差会累积

里程计的估计是有误差的，轮子打滑、地面不平都会让「走了多远」的估计慢慢偏离真实值。更麻烦的是，这个误差是**累积**的——走 1 米差 1 厘米，走 100 米就差 1 米。

这就是为什么只靠里程计建图，走廊永远是歪的。SLAM 算法的很大一部分工作，就是在和「累积误差」较劲，而最有力的武器，就是下一节说的回环检测。

## 三、回环检测：认出「这地方我来过」

回到外卖骑手的例子：他绕了一圈回到大门，一眼就认出来「这不就是我进门的地方吗」——这一瞬间，他脑子里一路累积的偏差，突然有了一个矫正的锚点。

SLAM 里的**回环检测（Loop Closure）**干的就是这件事：

1. 机器人边走边存「特征快照」——当前看到的激光特征长什么样；
2. 每走一步，拿当前帧和历史快照比对：「这个角落的轮廓，我是不是见过？」
3. 一旦确认是同一个地方，就建立一条「回环约束」：「第 500 步的位置」和「第 50 步的位置」其实是同一个点；
4. 后端优化器收到这条约束，把整条轨迹做一次全局调整——把中间累积的误差摊平。

> **回环检测是建图质量的救命稻草：有没有回环，走廊就是直的和歪的区别。**

这也是为什么很多建图教程会建议你「故意绕回起点」——不是迷信，是给算法制造一次矫正自己的机会。

## 四、激光 SLAM 到底是怎么「看」世界的

我们项目里用的是 2D 激光雷达，一圈 360 度，每一圈返回几百个「点」——每个点就是一个「距离 + 角度」：在这个方向上，离最近的障碍物有多远。

### 单帧激光能干什么

单独一帧激光，其实是一堆孤立的点。但相邻的两帧之间，这些点是有**重叠**的——你往前走 10 厘米，这面墙在前后两帧里都在，只是距离近了 10 厘米。

**激光 SLAM 的前端（Frontend）**干的就是这件事：用前后两帧（或多帧）激光数据做「扫描匹配（Scan Matching）」——

> 「如果机器人真的只走了 10 厘米，那这一帧和上一帧的墙应该能严丝合缝地对上。对不上，就说明里程计的估计错了，以墙为准。」

墙是不会动的，所以「以墙为准」永远比「以轮子为准」可靠。

### 后端在干什么

前端只管「这一步走得准不准」，是局部的。**后端（Backend）**管全局——它把整条轨迹和所有回环约束放在一起，做一次大优化：「在满足所有约束的前提下，整条轨迹怎么摆，地图误差最小。」

所以激光 SLAM 的经典分工是：

| 模块 | 职责 | 频率 |
| --- | --- | --- |
| 前端（Frontend） | 相邻帧匹配，估这一步的位置 | 高频，每帧都算 |
| 回环检测 | 认出没见过的地方 | 中频，持续比对 |
| 后端（Backend） | 全局优化，摊平累积误差 | 低频，发现回环才动 |

## 五、在 ROS 2 里亲手跑一遍

理论说了这么多，不如亲手跑一次。ROS 2 里最省心的激光 SLAM 方案是 `slam_toolbox`——它现在是 Nav2 项目官方推荐的建图组件之一，Humble 直接能装。

### 第一步：安装

```bash
sudo apt install ros-humble-slam-toolbox
```

### 为什么是 slam_toolbox，而不是别的

ROS 里能建图的方案不止一个，先把选型说清楚，免得以后踩错坑：

| 方案 | 状态 | 一句话评价 |
| --- | --- | --- |
| **slam_toolbox** | ROS 2 官方活跃维护 | 开箱即用，Nav2 生态原生集成，新项目首选 |
| cartographer_ros | 谷歌出品，更新放缓 | 精度和回环强，但配置复杂，ROS 2 支持一般 |
| gmapping | 经典老前辈，已停止维护 | 只适合跑 rosbag 怀旧，新项目别用 |

一句话：**新项目无脑上 slam_toolbox，有历史包袱才考虑 Cartographer。**

### 第三步：跑起来

如果你手上有真实的激光雷达和机器人底盘，把它们的数据发出来后，一条命令就能启动建图：

```bash
ros2 launch slam_toolbox online_async_launch.py
```

没有真机也不要紧，可以用 Gazebo 仿真环境配合一个带激光雷达的小车模型，效果完全一样——甚至更适合第一次练习，因为撞不烂东西。

启动后打开 RViz，添加 `/map` 话题，就能看到地图一点点「长」出来——机器人走到哪里，哪里就从「未知（灰色）」变成「可走（白色）」，墙和障碍物以黑色描边。

### 第四步：建完图一定要存

地图跑完了，别直接关终端——存盘：

```bash
ros2 run nav2_map_server map_saver_cli -f ~/maps/my_first_map
```

这条命令会生成两个文件：

| 文件 | 内容 |
| --- | --- |
| `my_first_map.pgm` | 地图本体，一张灰度图 |
| `my_first_map.yaml` | 元数据：分辨率（每个像素几米）、原点位置、阈值 |

> **建图跑得好，忘了存，等于白跑——我自己就因为这个重跑过一次。**

## 六、建出来的图，到底是什么

很多教程只讲怎么跑，不讲「跑出来的是个啥」，导致初学者看到 `.pgm` 一脸懵。这里专门说清楚。

SLAM 建出来的最常见的地图形式叫**占据栅格地图（Occupancy Grid）**——本质就是一张灰度图片：

- 白色像素：这里是**空的**，机器人可以走；
- 黑色像素：这里有**障碍物**，不能走；
- 灰色像素：这里是**未知区域**，还没探到。

`.yaml` 文件里最要紧的一个参数是 `resolution`——每个像素代表现实中多少米，常见值是 `0.05`，也就是 5 厘米一格。这就是为什么导航模块做路径规划时，能精确到「前面 10 厘米有个桌腿」。

> **机器人「认路」，认的不是什么高深的东西——就是一张分辨率为 5 厘米的灰度图。**

上一篇说的「路径规划」，规划的就是在这张图上，从起点到终点，找一条只走白色像素的线。

## 七、常见误区

**误区一：建图质量看运气。**
不是。建图质量主要取决于三个东西：走多慢、转多快、有没有回环。慢慢走、少急转弯、故意绕回起点，质量肉眼可见地提升。

**误区二：雷达越贵，图越好。**
雷达只是提供原始数据，算法和走法的影响大得多。一个便宜的 2D 激光雷达，慢慢走 + 制造回环，比高端雷达瞎跑强得多。

**误区三：建好一张图就一劳永逸。**
环境会变——桌子挪了、椅子搬了、季节变了。工程上的做法是**定期重扫**，或者用「动态地图」方案，让机器人持续更新地图。我们项目里就是每次巡检前做一次快速重扫，保证地图是最新的。

**误区四：SLAM 只能在室内用。**
2D 激光 SLAM 在室内、走廊、厂房这类结构化环境里效果最好；但在开阔的室外，特征太少，2D 方案会很吃力——那是 3D 激光或者视觉 SLAM 的地盘。

**误区五：玻璃门和镜子不会出问题。**
会，而且是我们项目里真实翻过的车。激光打在玻璃上要么穿过去、要么乱反射，地图上会凭空多出一堵「假墙」或者缺一段真墙。遇到大面积玻璃的场景，建图时要人工核对一遍，必要时在地图上手动画上禁行区。

## 八、一句话总结

- SLAM 就是**边走边干两件事：用地图定位，用定位建图**，两件事互为前提，同时推进；
- 核心矛盾是**鸡生蛋**：定位要地图，建图要定位——靠交替推进破解；
- **回环检测**是救命稻草：认出「我来过」，就能矫正一路累积的误差；
- 激光 SLAM 的分工是**前端管每一步、后端管全局**；
- 建出来的东西，就是一张**5 厘米一格的灰度图**——导航要的就是它；
- 工程上，**慢走、少急转、制造回环、定期重扫**，比换贵雷达管用。

学 SLAM 不用一上来就啃概率图模型，但要能回答三个问题：定位和建图为什么互为前提？回环检测解决什么问题？建出来的图到底是什么格式？这三个想通了，再深入就顺了。
